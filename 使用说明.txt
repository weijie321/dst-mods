CrashTrace Viewer 使用说明

一、这是什么

CrashTrace 分为两部分：

1. dst-mod-crash-tracer
   创意工坊里的诊断 mod，负责在游戏运行时记录异常上下文。

2. CrashTraceViewer.exe
   独立的 Windows 查看工具，负责读取你电脑上的 DST 日志，并生成更容易看懂的报告。

二、它能帮你做什么

当 mod 报错时，它会尽量告诉你：

- 最可疑的是哪个 mod
- 问题是在什么动作下触发的
- 目标对象是什么
- 应该先检查哪个文件

三、适用范围

- 当前只支持 Windows
- 不需要安装 Python
- 主要用于分析 Lua 层 mod 异常
- 不保证捕获引擎层、内存耗尽或进程级闪退

四、使用步骤

1. 订阅并启用 dst-mod-crash-tracer
2. 正常进入游戏
3. 触发一次 mod 异常
4. 退出游戏，或切回桌面
5. 双击 CrashTraceViewer.exe
6. 等待工具自动生成并打开 latest_crashtrace_report.txt

五、工具会读取哪里

默认读取：

- Documents\Klei\DoNotStarveTogether\client_log.txt
- Documents\Klei\DoNotStarveTogether\backup\client_log\*.txt
- Documents\Klei\DoNotStarveTogether\server_log.txt

六、你会看到什么

报告通常会直接给出：

- 最可疑 mod
- 触发动作
- 目标对象
- 错误原因
- 疑似出错文件
- 修复建议

七、如果没有报告

请按下面顺序排查：

1. 确认已经启用 dst-mod-crash-tracer
2. 确认这次真的触发过 mod 异常
3. 确认 DST 已经生成 client_log.txt 或 server_log.txt
4. 如果是非常早期的闪退，可能只剩 DST 原生日志，报告信息会比结构化捕获少
5. 如果你是服主，再确认问题发生在客户端、Master 还是 Caves

八、什么时候结果可能不完整

以下场景里，信息可能会比平时少：

- 游戏在很早阶段就闪退
- 属于引擎层或进程级崩溃
- 异常发生在 CrashTrace 加载前

九、给问题反馈时建议一起提供

- latest_crashtrace_report.txt
- 触发问题的大概操作步骤
- 你启用了哪些 mod
- 如果是服务器问题，补充说明是 Master 还是 Caves
